## Project Overview

**多协议桌面充电站3.0 (Multi-Protocol Desktop Charging Station V3.0)** — an ESP32-S3 based embedded firmware for a smart desktop charging station with a 240x240 TFT display, LVGL GUI, multi-protocol charging output control, power monitoring, WiFi web control, and weather display.

- MCU: ESP32-S3 (ESP32-S3-DevKitC-1)
- Framework: Arduino (via PlatformIO)
- GUI: LVGL 8.3.11 + SquareLine Studio 1.5.1 generated UI
- Display: 240x240 TFT (TFT_eSPI driver)
- License: CERN-OHL-P v2
- Open-source hardware: https://oshwhub.com/ikalyes/duo-xie-yi-zhuo-mian-chong-dian-zhan-3-0

## Build & Development Commands

```bash
# Build firmware
pio run

# Build and upload to device
pio run --target upload

# Monitor serial output (115200 baud)
pio device monitor

# Clean build
pio run --target clean

# Build with debug enabled (#define ENABLE_DEBUG 1 in main.h)
# Debug is enabled by default — serial output at 115200
```

There are no unit tests in this project (the `test/` directory contains only a README). Verification is done by flashing and observing device behavior.

## Project Architecture (High Level)

### Entry Point
- **`src/main.cpp`** — `setup()` initializes all subsystems in order (GPIO → flash → display → sensors → input → WiFi → NTP → weather → web server), then applies all switch states. `loop()` drives display, web server, time sync, and WiFi configuration handling.

### Core Modules (`src/`)

| File | Responsibility |
|---|---|
| `main.cpp/h` | System initialization and main loop |
| `display.cpp/h` | TFT display + LVGL init, backlight control (LEDC ch0), screen rotation, flush callback |
| `gpio.cpp/h` | GPIO pin defines + switch control (USB-C, USB-A) + fan PWM (LEDC ch1) + `TempControl_Fan()` temp-based speed |
| `adc.cpp/h` | ADC voltage/temperature sensing (3 channels, NTC thermistor, moving-average filter) |
| `ina219.cpp/h` | INA219 I2C current sensor on **Wire1 (I2C1)** — system power monitoring |
| `ina3221_service.cpp/h` | INA3221 3-channel I2C current sensor on **Wire (I2C0)** — per-port monitoring + RGB LED integration |
| `key.cpp/h` | 3-button input (GPIO 39/40/41: left/enter/right), provides an LVGL keypad input device |
| `lvgl_group.cpp/h` | LVGL group/screen navigation: which widgets are focusable on each screen |
| `lvgl_event.cpp/h` | **Live UI event handlers** (`ui_event_*` functions); umbrella include for UI helper/event/theme headers |
| `flash.cpp/h` | NVS (Preferences) persistence — all settings in one `"setting"` namespace |
| `variables.cpp/h` | Global state variables (switch states, sensor readings, config) |
| `rgbled.cpp/h` | Adafruit NeoPixel RGB LED control (3 LEDs, power→hue "breathing" effect) |
| `wifi_service.cpp/h` | WiFi connection + WiFiManager captive portal provisioning (AP SSID `ChargingStation`) |
| `weather.cpp` | 和风天气 (QWeather) API client (JSON + gzip decompression) |
| `main_service.cpp/h` | NTP time sync + weather refresh coordination (LVGL timer driven) |
| `web_server.cpp/h` | ESPAsyncWebServer + WebSocket; contains the entire embedded web dashboard (HTML/JS in `index_html`) |

### UI Layer (`src/ui/`)

Generated by **SquareLine Studio 1.5.1** (LVGL v8.3.11). Re-generate from the SquareLine project under `UI/` (`.sll`/`.spj` files) rather than editing the screen files by hand.

| Screen file | Purpose |
|---|---|
| `ui_MainScreen.c` | Main dashboard: output switches, per-port voltage/current/power, system temp |
| `ui_SettingScreen.c` | Settings: brightness slider, screen rotation, fan/manual-thermal control, WiFi/advanced entry |
| `ui_AdvancedSettingScreen.c` | Advanced: ADC calibration adjust (USB-A ports, thermometer), temp control toggle, time sync, LED toggle |
| `ui_WiFiScreen.c` | WiFi provisioning: start config portal, reset WiFi, show SSID/IP/sync time |
| `ui_WeatherScreen.c` | Weather display: temp/humidity, weather icon, clock, system power readings |

**Event handlers live in `src/lvgl_event.cpp`, not in the generated UI files.** Each screen's init function registers callbacks with `lv_obj_add_event_cb(widget, ui_event_*, LV_EVENT_ALL, NULL)`, where `ui_event_*` is implemented in `lvgl_event.cpp`. The generated `src/ui/ui_events.c` contains only no-op stubs (`// Your code here`) that `lvgl_event.cpp` calls for API compatibility — do not put behavior there. To change what a control does, edit the matching `ui_event_*` function in `lvgl_event.cpp`.

### Data Flow

```
Sensors (INA219, INA3221, ADC)
    │  LVGL timers
    ▼
Global variables (variables.h/.cpp)
    │
    ├──► LVGL UI labels updated via lv_label_set_text()
    ├──► WebSocket broadcasts sensor data to web UI
    └──► RGB LED colors set from INA3221 power readings

User Input (LEFT/ENTER/RIGHT buttons)
    │
    ▼
LVGL input device (key.cpp) → LVGL group navigation → Event handlers (lvgl_event.cpp)
    │
    ├──► GPIO switch toggles (USB-C, USB-A, fan)
    ├──► Setting persistence (flash.cpp → NVS)
    ├──► Screen transitions via lvgl_group.cpp
    └──► WiFiManager portal trigger
```

### Key Design Conventions

- **Sensor polling**: All periodic sensor reads use `lv_timer_t` created in each module's own init function (after `display_init()` has called `lv_init()`), not FreeRTOS tasks. Timer periods: ADC 200 ms, INA219 100 ms, INA3221 100 ms, RGB LED 1 ms, NTP clock refresh 500 ms. The WebSocket sensor broadcast is the exception — `web_server_run()` (called from `loop()`) uses a `millis()`-based interval instead of a timer.
- **Persistence**: Settings stored in ESP32 NVS via `Preferences`, all under one namespace `"setting"` keyed by string names. `flash.cpp` groups save/load by concern: basic settings, switch states, advanced settings, web config, and WiFi config.
- **Global state**: All shared state lives in `variables.h` as `extern` declarations, defined in `variables.cpp`. Switch states, sensor readings, and config strings are global.
- **UI event handling**: Screen init files attach `ui_event_*` callbacks (defined in `src/lvgl_event.cpp`). Handlers update global variables, drive GPIO, persist to NVS, and change screens via `lvgl_group_to_*()`.
- **Input & navigation**: `key.cpp` registers an LVGL keypad indev for the 3 buttons. LEFT/RIGHT move group focus, or adjust a slider once ENTER selects it (ENTER toggles the slider into edit state; LEFT/RIGHT then change its value, 200 ms debounce). `lvgl_group.cpp` defines which widgets are focusable per screen — adding a screen requires a matching `lvgl_group_to_<screen>()` function plus group membership.
- **Switch control**: `setTypeC32Output()` / `setTypeC1Output()` / `setUSBAOutput()` / `setFan()` / `setFanTempControl()` / `setChargeLed()` in `web_server.cpp` are the single choke point for every switch: they drive the GPIO, sync the LVGL widget's checked state, persist to NVS, and broadcast over WebSocket. Both the UI event handlers and the web UI route through these.
- **Screen rotation**: Handled at the LVGL display driver level via `display_set_rotation()`, with TFT_eSPI rotation under the hood.
- **Chinese text**: Custom fonts `ui_font_CHN` and `ui_font_CHN18` are used for Chinese characters. ASCII mono fonts are sized 16/20/32/40/56.
- **Weather API**: Uses 和风天气 (QWeather) `GET https://<host>/v7/weather/now?location=<cityCode>&key=<apiKey>` with gzip-compressed JSON responses, decompressed via ArduinoUZlib. Weather-code→icon mapping is `get_weather_icon()` in `main_service.cpp` (icons named `ui_img_<code>_png`).

### Web Control Protocol

The web dashboard is fully embedded in `web_server.cpp` (`index_html` PROGMEM string served at `/`). Browsers connect to the WebSocket at `/ws`:

- **Client → device**: `{"action":"switch","type":"<typeC32|typeC1|usbA|fan|fanTemp|chargeLed>","state":<bool>}`
- **Device → client**: switch-state JSON `{"switches":{...}}` sent on connect/change, plus periodic sensor JSON from `sendSensorData()` — `mainPower` (INA219), `group1..3` (INA3221, with channel↔group numbering reversed), `usbA4`/`usbA5` (ADC), `systemTemp`, `time`.
